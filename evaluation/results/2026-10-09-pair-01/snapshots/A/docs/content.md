# Content and routes (IU-CONTENT)
Authored records live in content/pages/en and pl. The single route catalogue is content/shared/routes.json. Each page unit adds its own pair, private provenance and source revision; UI receives only getPageView/publicView. Nothing fetches raw records in the browser. Page IDs drive every route, ancestor, project sibling, CTA and language equivalent.
Use editPair for factual changes (invalidates both languages and facts); editRecord for wording or media changes. Reviews are fingerprints, so manual edits cannot retain eligibility. seed uses exclusive creation, never overwrites edits and never imports approval. Restore the previous JSON from a saved source copy and rebuild; compare its fingerprint. Assets and captions are reviewed together. All real records start draft/unreviewed.
To add a page, register one stable ID and both routes, extend PageId, create both records with unique matching sections, add the purpose-specific template if needed, and run check, browser routes and accessibility. Invalid/reserved IDs, duplicate pairs, missing languages and broken related identities fail validation. Public export also requires all 34 reviewed records, origin, asset, privacy and receiver approvals. Current public export is deliberately blocked; isolated test approvals are not actual company approval.

All 17 identities and 34 records are now present. `getPages()` enforces complete pairs and page-specific required section IDs. Review fingerprints include every reviewable public/source field, including the Home visual caption, and exclude the mutable review stamps themselves. `tests/content.test.ts` edits every actual record in memory, verifies counterpart invalidation and unchanged unrelated records, and rejects missing required sections. It also checks a complete isolated approved publication fixture without changing real draft state. The real publication command reads private approval configuration and still rejects unreviewed records.
