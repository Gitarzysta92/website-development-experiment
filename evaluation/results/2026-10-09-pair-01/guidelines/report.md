# Evaluation against website-creation-guidelines

Evaluated 10 October 2026. Pair `2026-10-09-pair-01`, frozen first deliveries: **A = detailed**, **B = inputs-only**.

**Detailed has stronger demonstrated compliance with the library, especially for enquiry handling, content boundaries and technical verification. Neither implementation fully satisfies it.** The most consequential gaps are B's missing enquiry receiver, revision-approval defects in both sites, and A's build prerequisite rejecting approved content. Both also violate the sticky-panel fit rule.

**Second pass, 10 October 2026:** executed runtime checks add G-03 (both lose the active artifact on injected activation failure) and GA-04 (A's gateway crashes on a malformed request target). A's local recovery and B's representative font-failure behavior now have passing evidence. Current counts below incorporate these changes. See the [second-pass findings and evidence](/Users/michal.lukasiewicz/Programming/website-development-experiment/evaluation/results/2026-10-09-pair-01/guidelines/pass-02/report.md).

This is a separate audit from the earlier shared website-quality comparison. B was not given the guideline library; its results are an external benchmark, not a claim that it disobeyed instructions. Stronger guideline compliance does not establish stronger visual design or an overall experimental winner.

## Technical architecture and nonfunctional requirements

Expanded on 10 October 2026 after the technical assessment was underrepresented in the initial summary. The earlier shared-quality rubric gives engineering/handover 10% and performance 5%, with accessibility/responsiveness assessed separately. Architecture, maintainability and operability have no separate weighted scores. That frozen rubric must not be read as a complete engineering-readiness verdict, and its weights have not been changed after seeing results.

## Consequential findings

### B-01: Selected enquiry receiving capability is missing

**Major; current functionality. Rules FORM-02 through FORM-05 and FORM-08.** The Contact form validates input and prepares a copyable email draft. It makes no receiving request; the preview server rejects writes with 405. Visitors must send the draft through their own email application. This is useful and honestly described, but does not implement the shared receiving-and-routing objective. Credentials alone cannot complete it: receiving code is also needed.

A has a functioning local synthetic receiver with acceptance receipts and duplicate handling. That verifies local receipt only; real mailbox delivery and live notification behavior remain unverified.

Evidence: [B draft controller](/Users/michal.lukasiewicz/Programming/website-development-experiment/evaluation/results/2026-10-09-pair-01/snapshots/B/public/client.js:157), [B server write rejection](/Users/michal.lukasiewicz/Programming/website-development-experiment/evaluation/results/2026-10-09-pair-01/snapshots/B/server.mjs:61), [independent interaction results](/Users/michal.lukasiewicz/Programming/website-development-experiment/evaluation/results/2026-10-09-pair-01/evidence/interactions/adjudicated-results.json), [form rules](/Users/michal.lukasiewicz/Programming/website-creation-guidelines/rules/capabilities/forms.md).

### GA-02 and GB-03: Approvals do not cover all relevant changes

**Major; latent release-path defects. Rules REL-03, CMS-04 and LANG-06.** These concern the implemented approval mechanisms; no real approval or publication occurred.

- **A / GA-02:** The approval fingerprint covers the page JSON record. The rendered page also imports a separate diagram with localized descriptions. In a disposable approved fixture, changing the English diagram description changed its file hash, but the page remained eligible and the direct publication gate still accepted all 34 records. Record edits invalidate approval correctly; externally rendered dependencies are the gap. The independent build blocker below currently prevents an ordinary published build, so this is not evidence that a changed diagram was successfully released.
- **B / GB-03:** Approval is represented by global `CONTENT_APPROVED` and `SITE_INDEXABLE` booleans. A disposable build succeeded, then succeeded again after homepage copy changed under the same flags; the changed artifact still contained `index,follow`. There is no revision or language-specific invalidation. The local preview server remains non-indexable; the demonstrated issue is the generated release artifact.

The appropriate contract is to bind review to the relevant content and rendered dependencies, including language and media revisions, and require renewal when those change.

Evidence: [A fingerprint and gate](/Users/michal.lukasiewicz/Programming/website-development-experiment/evaluation/results/2026-10-09-pair-01/snapshots/A/src/content/publication.mjs:2), [A external diagram import](/Users/michal.lukasiewicz/Programming/website-development-experiment/evaluation/results/2026-10-09-pair-01/snapshots/A/src/templates/aifield-ai/Page.astro:8), [B approval flags](/Users/michal.lukasiewicz/Programming/website-development-experiment/evaluation/results/2026-10-09-pair-01/snapshots/B/build.mjs:24), [mutation-probe results](/Users/michal.lukasiewicz/Programming/website-development-experiment/evaluation/results/2026-10-09-pair-01/guidelines/evidence/source-probes.json), [REL-03](/Users/michal.lukasiewicz/Programming/website-creation-guidelines/rules/operations-and-lifecycle.md:59), [CMS-04](/Users/michal.lukasiewicz/Programming/website-creation-guidelines/rules/capabilities/cms.md:19), [LANG-06](/Users/michal.lukasiewicz/Programming/website-creation-guidelines/rules/capabilities/languages.md:27).

### GA-03: Detailed's build prerequisite requires content to remain unapproved

**Major; latent release-path blocker. Rules QA-02 and TECH-13.** The documented build invokes `scripts/check-content.mjs`, which runs the real authored-content tests before its publication gate. A test requires every record's reviews to be null and its editorial state to be `draft`. In a disposable fixture with 34 approved records accepted by the direct gate, the prerequisite exits 1 at that assertion: six tests pass and one fails.

This is an implementation blocker independent of missing owner approvals, receiver credentials or hosting. A useful acceptance check would exercise the real approved-record build path in addition to rejecting unapproved input, with draft-specific expectations confined to draft fixtures.

Evidence: [draft-only assertions](/Users/michal.lukasiewicz/Programming/website-development-experiment/evaluation/results/2026-10-09-pair-01/snapshots/A/tests/content.test.ts:18), [build preflight](/Users/michal.lukasiewicz/Programming/website-development-experiment/evaluation/results/2026-10-09-pair-01/snapshots/A/scripts/runtime/build.mjs:5), [reproduced failure log](/Users/michal.lukasiewicz/Programming/website-development-experiment/evaluation/results/2026-10-09-pair-01/guidelines/evidence/A-approved-content-check.log), [QA-02](/Users/michal.lukasiewicz/Programming/website-creation-guidelines/rules/verification.md:13), [TECH-13](/Users/michal.lukasiewicz/Programming/website-creation-guidelines/rules/technical-conventions.md:63).
