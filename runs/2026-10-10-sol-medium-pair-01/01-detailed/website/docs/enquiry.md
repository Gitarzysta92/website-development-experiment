# Enquiry operation

Browser `ContactForm.astro` POSTs JSON to the same-origin `/api/enquiries`. The pure Zod contract lives in `src/features/enquiry/domain/`; `application/` invokes a receiver port; only `server/` chooses the fixture, disabled or Resend adapter. The runtime host accepts only loopback preview traffic. No form values are persisted in the browser or URL, and the server does not log request bodies.

Fixture is the default local mode. It holds at most 1000 process-local ID/receipt entries, expires them within 24 hours on access, and clears all on restart. Matching IDs/payloads share one receipt; changed payloads conflict. A controlled test can inspect the fixture through its module API, not through a public HTTP route. `AF_RECEIVER=disabled` returns unavailable without storage or sending. `AF_RECEIVER=resend` remains disabled unless separately configured and authorized; the local host rejects a live-send activation. The Resend transport mapping, fixed sender/recipient, reply-to and idempotency key are tested with a fake transport only. No real provider call or mailbox delivery occurred.

Endpoint limits: JSON POST, 32 KiB streamed body, exact fields, same-Origin, 5 attempts/minute per direct peer in a bounded process-local map, 10-second upstream abort, and no public CORS grant. The browser waits up to 12 seconds and retains an unchanged ID/body for a user-initiated retry within 23 hours. A timeout after dispatch is uncertain. This limiter is suitable only for the single-process loopback preview; a distributed deployment needs an approved shared topology.

Before any live activation, the user must identify an enquiry operator and approved mailbox, verify sender and recipient, supply a server-held API key through a secret connection, approve provider/data retention and a production privacy notice, authorize external sending, and validate actual delivery to the operator mailbox. Provider acceptance alone does not prove mailbox receipt. Those actions are outside this local experiment.
