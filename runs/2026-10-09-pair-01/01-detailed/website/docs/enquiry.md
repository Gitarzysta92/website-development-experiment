# Enquiry (IU-ENQUIRY)
Contact/Privacy own the complete EN/PL experience. Presentation posts only JSON to /api/enquiries; the endpoint enforces method, actual bytes, origin and rate limits before the pure submit use case validates and dispatches through EnquiryReceiver. The server/index composition root alone chooses fixture, disabled or Resend. The default fixture never sends email. Tests inject transport; no external provider call is authorized.
Only synthetic data is allowed locally. Fields and limits follow ENQ-1.0. Process memory is bounded to 1000 entries; fixture receipts and idempotency records expire at 24h and clear on restart. Cleanup is lazy on access. There is no database, cookie, payload log or browser persistent storage. Retry cutoff is 23h. Rate limit is 5/min per direct local peer, not distributed protection. The upstream deadline is 10s; browser wait is 12s. Uncertainty never becomes success. Same ID with different normalized payload conflicts. Unchanged retry retains serialized provider bytes and idempotency header.
The public email remains a supplied, unverified candidate. Opening mailto is distinct from local receipt and any mail the visitor sends independently.
Use ENQUIRY_MODE=disabled to test unavailable mode. Resend requires verified sender, fixed recipient, server key and a private activation JSON path in AF_LIVE_ACTIVATION_RECORD. Its schema in config/server.ts requires actual external-send authority, operator, data policy, retention procedure, origin and supported topology evidence. Missing/mismatched configuration selects disabled, never fixture. A public/proxy deployment requires a revised topology contract. No activation file is included or synthesized.
AF_TEST_RECEIPT_OBSERVER=1 allows a private parent-process IPC receipt observer for browser integration. It emits only receipt ID, submission ID and count, never form contents. There is no inspection HTTP route. Unit tests inspect full synthetic receipts through the receiver's in-process test API.
To add a receiver, implement the domain port, bind once in server/index, test mapping with a controlled transport, and verify actual receipt separately from UI. Real provider acceptance, operator mailbox receipt, data review and publication remain external prerequisites.

Final lifecycle repair: pagehide aborts in-flight browser work, increments its generation and leaves a retryable uncertain state with the original request ID/body. This avoids a disabled form after a cached-page restoration. The stale-response browser test explicitly exercises the persisted pagehide transition. Process-memory entries have active expiry timers as well as access-time pruning, so inactivity does not retain payloads indefinitely.
