Each file in `units/` is a prewritten prompt for a concrete component/capability/page. Its complete concern matrix binds content, behavior, design, accessibility, implementation, performance, discovery, data/security, editing and verification to that piece. There are no discipline/phase units. Units consume these shared records instead of duplicating the requirements. Read a unit together with its referenced contracts; the plan is the only authoritative schedule.

The input brief's objectives OBJ-01 through OBJ-10 remain the source inventory. [The plan](implementation-plan.md#objective-coverage) binds them to the local experiment and records the limitations on review, live delivery, and release. The source documents retain their historical/proposed status; accepted decisions here resolve only the specified choices.

The process dependency referenced by `inputs/references/guidelines-reference.md` is available at [the pinned local library](../knowledge/website-creation-guidelines/README.md). Its rules remain authoritative definitions. This package binds project-specific values and actions; it does not redefine rule IDs or inherit Wapps' framework.
