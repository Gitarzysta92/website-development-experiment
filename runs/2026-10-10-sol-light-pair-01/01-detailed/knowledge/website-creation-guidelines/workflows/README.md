# Workflows

Workflows apply the library's [rules](../rules/README.md), [capability contracts](../capabilities/README.md) and [guides](../guides/README.md). They produce records and implementation in the target project using the existing [templates](../templates/README.md).

| Workflow | Use when | Main inputs | Expected outputs |
| --- | --- | --- | --- |
| [Prepare creation inputs](prepare-creation-inputs.md) | A request and available materials need to be assembled | Initial request, available sources, supplied authority and existing records | Brief, objective inventory, selected workflow references, execution policy, candidate capabilities, decisions and preparation handoff |
| [Compile implementation units](../compilation/compile-implementation-units.md) | Full agreed scope needs to become a complete implementation package | Project inputs/policy, knowledge, selected workflows and existing context | Chosen structure, all unit contracts, complete plan, coverage, completeness and mode-specific acceptance |
| [Execute an implementation plan](../implementation/execute-implementation-plan.md) | A complete package has been accepted under the supplied policy | Exact plan/unit manifest, declared inputs, current implementation, execution policy and evidence | Actual artifacts, execution records, check evidence, controlled revisions and plan completion/blocker records |
| [Create a website](create-website.md) | Planning, implementing, verifying and operating the agreed website | Prepared or incomplete brief, materials, applicable rules and existing context | Implementation, current project records, acceptance evidence and an explicit release/handover outcome |
| [Add a page or feature](add-page-or-feature.md) | Extending an existing implementation | Requested change, current implementation/records and relevant prior evidence | Implemented change, updated records, scoped verification and release handoff if in scope |

Each procedure and each named stage declares its inputs and outputs, including conditional inputs and the authoritative target-project location of the result. Missing information stays explicit during preparation. Resolve consequential definition gaps before the package is complete; declared future outputs can remain execution prerequisites. Expected deliverables are not evidence of completion. Publication, recurring work and external commitments follow the project's existing authority and scope.

The compilation procedure lives with its guide, unit and plan formats in [compilation](../compilation/README.md). Execution lives with its guide and record format in [implementation](../implementation/README.md). Creation compiles all units and the plan during specification. Later material changes revise affected units/consumers and the plan, validate the entire replacement package and follow policy-based acceptance before affected execution.
